# GitHub security setup

Observed via read-only GitHub API on 2026-09-08: repository public, personal account ownership (`User`), default branch master, GitHub Pages disabled; Secret Scanning and Push Protection enabled; Dependabot security updates disabled. Dependabot alert state and CodeQL default setup were not verified by this API response. No repository settings were changed.

1. Open `techilounge/KonnectedRoots` on GitHub, then **Settings → Security → Advanced Security** (some accounts show **Code security and analysis**).
2. Under Secret Protection, verify **Secret scanning** and **Push protection** are enabled. In **Security → Secret scanning**, review open and resolved alerts privately. Verify the rotated Stripe alert remains resolved. Do not dismiss server credential alerts as false positives.
3. Enable **Dependency graph**, **Dependabot alerts**, and **Dependabot security updates**. The last setting is currently disabled. Review generated upgrade PRs; do not auto-merge major upgrades.
4. Under Code scanning, inspect CodeQL setup. If **Default setup** is enabled, switch it off before enabling the committed **Advanced setup** workflow to avoid conflicting analyses. Merge `.github/workflows/codeql.yml`, then inspect **Actions → CodeQL** and **Security → Code scanning**. JavaScript/TypeScript scanning covers `src`, `functions/src` and scripts without running the application or needing credentials.
5. Review the pushed security branch's **Actions → Secret security** run. PR/push runs scan only newly introduced commit ranges, so revoked credentials in older shared history do not fail every PR. Once the workflow is on the default branch, **Run workflow** defaults to current-source scanning; explicitly enable `full_history` for the incident audit, which is expected to fail until cleanup. No secret allowlist suppresses the revoked credential. Require the normal `Gitleaks` check for PRs; a successful range scan does not close the historical incident.
6. Open **Settings → Rules → Rulesets → New branch ruleset**. Target `master`, `main` if used, and normal shared preview branches. Set enforcement to Active, require PRs, require review, dismiss stale approvals, require resolved conversations, and block force pushes and branch deletion. Keep bypass access restricted to the owner for an explicitly coordinated history rewrite.
7. Under **Require status checks to pass**, select the actual successful check names after each has run. Required policy: **build**, **typecheck**, **tests**, **Gitleaks**, **CodeQL**. This task adds Gitleaks/CodeQL only; if build/typecheck/tests are not separate GitHub checks, create CI jobs for them first rather than selecting nonexistent names. A production deployment status is not a typecheck/test replacement. Use trusted preview/deployment build validation for Firebase-dependent routes without sharing production secrets with forks.
8. Review Actions permissions: allow vetted actions, prefer immutable SHA pins, restrict write-token defaults, and require approval for first-time external contributors. Review changes to workflow/config/allowlist files as security-sensitive changes.
9. Before changing visibility, verify the paid/private-repository entitlement for Secret Protection, Code Security, and rulesets. Availability depends on account/plan; Gitleaks CLI remains usable independently.

References: [push protection](https://docs.github.com/en/code-security/how-tos/secure-your-secrets/prevent-future-leaks/enable-push-protection), [CodeQL configuration](https://docs.github.com/en/code-security/reference/code-scanning/workflow-configuration-options), [official Gitleaks action](https://github.com/gitleaks/gitleaks-action).
